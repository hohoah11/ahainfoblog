변경 요청서 양식, 변경 전후와 영향을 한 장에

현재 내용과 바꿀 내용, 변경 사유, 일정·비용·품질 영향을 입력하면 담당·팀장·대표 결재란이 있는 변경 요청서가 오른쪽 미리보기에 바로 만들어집니다. 다 쓴 문서는 A4로 인쇄하거나 PDF로 저장할 수 있습니다. 입력한 내용은 서버로 보내지 않고 이 브라우저 안에서만 처리합니다.

작성: 아하서식 편집팀 · 최종 검토: 2026년 11월 23일

이미 정한 것을 바꿀 때 남기는 문서

변경 요청서는 승인까지 끝난 계획을 바꿔야 할 때 씁니다. 납기, 사양, 예산, 담당 업체처럼 이미 확정된 내용이 대상입니다. "무엇을 어떻게 바꾸는지"와 "바꾸면 무엇이 달라지는지"를 한 장에 적어 결재권자의 판단을 받습니다.

메신저로 "오픈 2주만 미룰게요"라고 합의해도 일은 진행됩니다. 문제는 몇 달 뒤입니다. 예산이 왜 늘었는지, 누가 일정 연기를 허락했는지 물을 때 근거를 내놓기 어렵습니다. 변경 요청서는 이런 질문에 답할 수 있는 기록입니다. 법으로 정해진 양식이 없는 사내 문서이므로 회사 사정에 맞게 항목을 더하거나 빼도 됩니다.

빠뜨리면 다시 돌아오는 항목

항목적는 내용빠지면 생기는 문제
문서번호CR-2026-007처럼 연도와 순번같은 프로젝트의 여러 변경 건이 섞임
변경 대상일정, 사양, 예산, 인력 중 무엇인지결재자가 어느 계획서를 봐야 할지 모름
현재 내용승인된 계획서에 적힌 그대로"원래 어땠는지"를 두고 기억이 엇갈림
변경 내용바뀐 뒤의 값, 숫자와 날짜로"조금 늘림" 같은 표현이 해석 차이를 만듦
변경 사유요청 주체와 발생 원인책임 소재와 비용 부담 주체가 불분명
영향일정·비용·품질 각각의 변화승인 뒤에 추가 비용이 따로 드러남

프로젝트 계획서, 리스크 관리대장과 무엇이 다른가요

구분프로젝트 계획서변경 요청서리스크 관리대장
다루는 것처음 정한 목표·일정·예산이미 정한 것을 바꾸는 한 건아직 일어나지 않은 위험
작성 시점착수 전변경이 필요해진 때진행 내내 갱신
결재착수 전 승인건마다 승인보통 정기 점검
관계변경 승인 시 갱신 대상계획서를 고치는 근거위험이 현실이 되면 변경 요청으로 이어짐

작성 예시: 그룹웨어 교체 중 기능 추가

물류회사 한결로지스 경영지원팀 윤서진 과장이 사내 그룹웨어 교체 프로젝트를 맡았습니다. 개발 중 영업팀이 "모바일에서 전자결재 승인" 기능을 추가로 요청했습니다. 외주사 견적은 추가 공수 15MD(맨데이, 1인 1일 작업량), 1MD당 450,000원입니다.

칸현재 내용변경 내용
사양PC 전자결재만 제공모바일 전자결재 승인 추가
일정오픈 2026년 12월 14일오픈 2027년 1월 11일(4주 연기)
비용(공급가액)48,000,000원54,750,000원(+6,750,000원)
품질통합 테스트 2주통합 테스트 3주(모바일 기기 포함)

추가 비용은 15MD × 450,000원 = 6,750,000원으로, 기존 예산 대비 약 14.1% 늘어납니다. 일반과세 거래라면 부가세 10%를 더한 실제 지급액은 7,425,000원입니다. 공급가액 기준인지 부가세 포함 금액인지 영향 칸에 함께 적어야 결재자가 금액을 오해하지 않습니다. 변경 사유 칸에는 "영업팀 요청(외근 중 결재 지연), 외주사 견적서 첨부"처럼 요청 주체와 근거를 씁니다.

영향 칸 쓰는 요령. 일정·비용·품질 중 변화가 없는 항목도 "영향 없음"이라고 적으세요. 비워 두면 검토를 안 한 것인지 영향이 없는 것인지 구분되지 않습니다.

작성할 때 자주 하는 실수

1. 변경 내용만 쓰고 현재 내용을 생략하는 경우

"오픈일 1월 11일"만 적으면 며칠이 밀렸는지 결재자가 계획서를 다시 찾아봐야 합니다. 현재 내용은 승인된 계획서 문구를 그대로 옮기세요.

2. 비용만 적고 일정과 품질을 빼는 경우

기능 추가는 대개 일정과 테스트 범위도 함께 바꿉니다. 비용만 승인받으면 나중에 오픈일이 밀린 이유를 따로 설명해야 합니다.

3. 여러 변경을 한 장에 묶는 경우

기능 추가와 담당 업체 교체를 한 문서에 넣으면 하나만 승인하고 싶어도 결재가 막힙니다. 결정이 따로 필요하면 문서도 나누세요.

4. 승인 뒤 계획서를 고치지 않는 경우

변경 요청서만 쌓이고 계획서는 처음 그대로면, 새로 합류한 사람이 옛 일정을 기준으로 일합니다.

승인 뒤 기록을 남기는 순서

  1. 결재가 끝난 요청서를 PDF로 저장하고 파일 이름에 문서번호를 붙입니다.
  2. 프로젝트 계획서의 해당 항목을 고치고, 고친 자리 옆에 "CR-2026-007 반영"처럼 근거 번호를 적습니다.
  3. 외주 계약 금액이 바뀌었다면 계약서와 세금계산서도 바뀐 금액에 맞는지 경리 담당자와 확인합니다. 세금계산서 같은 증빙서류는 국세기본법에 따라 법정 신고기한이 지난 날부터 5년간 보관합니다.
  4. 반려된 요청서도 지우지 말고 보관합니다. 같은 요청이 다시 올라올 때 판단 근거가 됩니다.

자주 묻는 질문

결재란을 회사 직급에 맞게 바꿀 수 있나요?

이 도구의 결재란은 담당, 팀장, 대표로 표시됩니다. 직급 체계가 다르면 인쇄한 뒤 손으로 고쳐 쓰는 방법이 있습니다.

문서번호는 꼭 넣어야 하나요?

선택 항목입니다. 다만 한 프로젝트에서 변경이 두 건 이상 생기면 번호가 있어야 계획서와 연결하기 쉽습니다.

작은 변경도 요청서를 써야 하나요?

회사마다 기준이 다릅니다. 보통 일정·비용·외부 계약에 영향을 주는 변경은 문서로 남기고, 담당자 선에서 끝나는 문구 수정 등은 회의록으로 갈음하는 경우가 많습니다.

처음 써 보는데 어디서부터 채우나요?

"예시로 채워 보기" 버튼을 누르면 각 칸에 들어갈 내용의 예가 채워집니다. 미리보기를 보면서 자기 내용으로 바꿔 쓰면 됩니다.

입력한 내용이 저장되나요?

입력 내용은 서버로 전송되지 않습니다. 필요한 문서는 PDF로 저장해 두세요.
