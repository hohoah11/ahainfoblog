진행 상황 보고서 양식, 진행률과 이슈를 한 장에

세부 업무별 담당·기한·진행률과 주요 이슈를 입력하면 결재란이 있는 A4 보고서가 오른쪽에 바로 만들어집니다. 처음이라면 '예시로 채워 보기'로 완성된 모습을 먼저 확인해 보세요. 입력한 내용은 서버로 보내지 않고 이 브라우저 안에서만 처리합니다.

진행 상황 보고서는 언제 쓰나요

진행 상황 보고서는 진행 중인 프로젝트가 계획보다 앞서 있는지 뒤처져 있는지, 무엇이 막혀 있는지를 윗선이나 발주처에 알리는 문서입니다. 사무실 이전, 전산 시스템 교체, 신제품 출시 준비처럼 몇 주 이상 걸리고 여러 사람이 나눠 맡는 일에서 주로 씁니다.

보고 시점은 크게 두 가지입니다. 하나는 격주나 월 1회처럼 정해진 날에 내는 정기 보고이고, 다른 하나는 일정 차질이 확인된 직후에 내는 수시 보고입니다. 법으로 정해진 양식은 없습니다. 다만 읽는 사람이 첫 화면에서 "지금 괜찮은가, 내가 무엇을 결정해야 하나"를 알 수 있게 쓰는 것이 기본입니다.

항목적는 내용빠지면 생기는 문제
프로젝트명·보고일공식 프로젝트 이름, 보고 기준일몇 차 보고인지, 언제 기준 숫자인지 헷갈림

세부 업무·담당업무 한 줄에 담당자 한 명문제가 생겼을 때 누구에게 물어야 할지 모름
기한계획상 완료일. 바뀌었다면 원래 날짜도 함께지연 여부를 판단할 기준이 사라짐
업무별 진행률·상태퍼센트와 정상·주의·지연 같은 상태숫자만 보고 위험을 놓침
주요 이슈막힌 일과 보고받는 사람에게 바라는 것보고가 끝나도 아무 조치가 일어나지 않음
결재란담당, 팀장 확인보고를 받았다는 기록이 남지 않음

구분진행 상황 보고서주간 업무 보고서이슈 관리대장

답하는 질문계획 대비 어디까지 왔나이번 주에 무엇을 했나이 문제는 해결됐나
작성 방식보고할 때마다 새로 작성매주 새로 작성한 장에 계속 누적

이슈가 많아 보고서 한 장에 다 담기 어렵다면 이슈 관리대장에 따로 쌓아 두세요. 보고서에는 이번 보고 기간에 결정이 필요한 것만 올리면 됩니다.

전체 진행률은 이렇게 계산합니다

전체 진행률 칸은 직접 입력하는 칸입니다. 세부 업무의 퍼센트를 단순 평균하면 업무 크기가 반영되지 않기 때문에, 각 업무에 드는 작업량(예상 작업일수)을 가중치로 곱하는 방식을 흔히 씁니다. 물류회사 '한결물류'의 창고관리시스템 교체 프로젝트로 계산해 보겠습니다.

세부 업무담당예상 작업일수진행률완료 환산일수
요구사항 정리서지민10일100%10일
재고 데이터 이관남궁현20일40%8일
바코드 장비 설치육태경5일0%0일
현장 직원 교육서지민5일0%0일
합계40일18일

가중 진행률은 18 ÷ 40 = 45%입니다. 네 업무의 퍼센트를 단순 평균하면 (100 + 40 + 0 + 0) ÷ 4 = 35%로, 10%포인트 차이가 납니다. 어느 방식을 쓰든 매 회차 같은 방식을 유지해야 회차별 비교가 가능합니다.

진행률 매기기 팁. 업무별 퍼센트를 감으로 매기기 어렵다면 "시작 전 0%, 착수 50%, 완료 100%"처럼 단계를 정해 두는 방법도 흔히 씁니다. 숫자는 거칠어지지만 담당자마다 기준이 달라지는 일은 줄어듭니다.

지연을 보고할 때 빠뜨리면 안 되는 네 가지

위 예시에서 바코드 장비 설치는 기한이 12월 4일이었는데 아직 0%입니다. 이럴 때 "장비 입고 지연"만 적으면 읽는 사람이 다시 물어야 합니다. 아래 네 가지를 한 번에 적으세요.

  1. 원인: 공급업체 재고 부족으로 입고가 12월 15일로 밀림
  2. 영향: 설치 완료가 원래 기한보다 최소 11일 늦어지고, 뒤이은 현장 직원 교육도 그만큼 밀릴 수 있음
  3. 만회 계획: 장비 없이 할 수 있는 교육 자료 준비를 앞당겨 진행
  4. 결정 필요 사항: 다른 업체 장비로 바꿀지 여부를 12월 9일까지 결정 요청

지연은 확인한 즉시 보고하는 편이 낫습니다. 기한 당일에 알리면 선택지가 줄어듭니다. 만회 계획에 야근이나 추가 근무를 넣는다면, 상시 5인 이상 사업장에서 연장근로는 당사자 합의로 1주 12시간까지라는 점도 계획에 반영하세요.

이슈와 요청은 나눠서 적으세요

이슈는 "이미 일어난 문제"이고, 요청은 "보고받는 사람이 해 줘야 하는 일"입니다. 둘을 한 문장에 섞으면 문제 설명만 읽히고 요청은 묻히기 쉽습니다. 주요 이슈 칸에 아래처럼 머리말을 붙여 줄을 나누면 구분이 분명해집니다.

  • [이슈] 기존 시스템 재고 코드 중 약 300건이 중복되어 이관이 멈춤
  • [요청] 중복 코드 정리 기준을 물류팀과 협의할 수 있도록 회의 일정 조율 부탁드립니다

요청에는 누가, 언제까지 해 주길 바라는지를 적어야 실제 조치로 이어집니다.

작성할 때 자주 하는 실수

1. 들인 시간을 진행률로 적는 경우

작업일수 20일 중 12일을 썼다고 60%로 적으면 안 됩니다. 진행률은 끝낸 일의 양이고, 쓴 시간은 별개입니다. 시간은 많이 썼는데 결과물이 적다면 그것 자체가 보고할 이슈입니다.

2. 몇 주째 90%에 머무는 업무

마지막 10%에 예상보다 오래 걸리는 일이 흔합니다. 두 번 연속 같은 숫자라면 상태를 '주의'로 바꾸고 남은 일이 무엇인지 적으세요.

3. 지연을 '진행 중'으로 덮는 경우

기한이 지났는데 상태를 그대로 두면 다음 보고서에서 갑자기 큰 지연이 드러납니다. 기한이 지난 업무는 '지연'으로 표시하는 것을 원칙으로 하세요.

4. 바뀐 기한만 적고 원래 기한을 지우는 경우

"12/4 → 12/15"처럼 원래 날짜를 남겨야 지연 폭이 보입니다. 기한 칸에 두 날짜를 함께 적으면 됩니다.

자주 묻는 질문

처음 써 보는데 어디서부터 채워야 하나요?

'예시로 채워 보기' 버튼을 누르면 샘플 내용이 들어갑니다. 미리보기로 완성 모습을 확인한 뒤 내 프로젝트 내용으로 바꿔 쓰면 됩니다.

세부 업무가 많으면 어떻게 하나요?

목록 표는 줄을 추가하거나 삭제할 수 있습니다. 다만 줄이 너무 많으면 핵심이 흐려집니다. 작은 업무는 묶고, 보고받는 사람이 판단하는 데 필요한 단위까지만 나누세요.

발주처에 내는 보고서로 써도 되나요?

쓸 수 있습니다. 외부에 낼 때는 내부 담당자 사정보다 납기와 결과물에 미치는 영향을 중심으로 이슈를 적는 것이 좋습니다.

진행률은 소수점까지 적어야 하나요?

보통 정수로 충분합니다. 45.3%와 45%의 차이로 판단이 달라지는 일은 드뭅니다.

입력한 내용은 어디에 남나요?

입력 내용은 서버로 전송되지 않습니다. 작성을 마치면 PDF로 저장해 두세요.
