업무 요청서 양식, 기한과 결과물까지 한 장에

요청 부서와 수신 담당, 희망 완료일, 우선순위, 결과물 형태를 입력하면 오른쪽 미리보기에 업무 요청서가 바로 만들어집니다. 완성한 요청서는 A4로 인쇄하거나 PDF로 저장할 수 있습니다. 입력한 내용은 서버로 보내지 않고 이 브라우저 안에서만 처리합니다.

말로 부탁한 일이 자꾸 늦어진다면

업무 요청서는 다른 부서나 다른 팀 담당자에게 일을 맡길 때 쓰는 문서입니다. 무엇을, 언제까지, 어떤 형태로 받고 싶은지를 적어 전합니다. 상급자가 내리는 지시와 달리 대등한 부서끼리 협조를 구하는 문서입니다. 그래서 받는 쪽이 내용을 정확히 이해하고 일정을 잡을 수 있게 쓰는 것이 핵심입니다.

복도에서 "그 자료 좀 부탁해요"라고만 말하면 빠지는 정보가 생기기 쉽습니다. 기준일이 언제인지, 파일로 줄지 출력물로 줄지, 이번 주 안에 필요한지가 정해지지 않습니다. 영업지원팀이 회계팀에 미수금 자료를 받거나, 총무팀이 IT 담당에게 신규 입사자 계정 발급을 맡기는 경우가 그렇습니다. 받은 결과물을 다른 업무에 바로 써야 한다면 요청서로 정리해 두는 편이 좋습니다. 업무 요청서는 법으로 정해진 양식이 없는 회사 내부 문서입니다. 아래 항목을 기본으로 회사 사정에 맞게 고쳐 쓰면 됩니다.

요청서에 빠지면 안 되는 항목

항목적는 내용빠지면 생기는 문제
요청 부서·요청자부서명, 이름, 직급궁금한 점이 생겨도 누구에게 물어야 할지 모름
수신 부서·담당부서명과 실제 처리할 담당자 이름부서 전체에 보내면 서로 미루다 방치됨
요청일요청서를 전달한 날처리 기간이 며칠이었는지 나중에 확인할 수 없음
희망 완료일결과물을 받아야 하는 날짜"급한 건 줄 몰랐다"는 말이 나옴
우선순위긴급·높음·보통 등 회사 기준받는 쪽이 여러 요청의 처리 순서를 정할 수 없음
요청 제목한 줄로 요약한 요청 내용메일함이나 서류철에서 다시 찾기 어려움
요청 내용배경, 범위, 기준일, 조건엉뚱한 범위로 작업해 다시 해야 함
결과물 형태엑셀 파일, 보고서, 출력물, 시스템 반영 등받은 결과물을 다시 가공하느라 시간이 듦

업무 지시서·품의서·발주서와 무엇이 다른가요

이름이 비슷해서 섞어 쓰는 경우가 많습니다. 하지만 누가 누구에게 무엇을 구하는지에 따라 써야 할 문서가 다릅니다.

구분방향목적주로 쓰는 때
업무 요청서부서와 부서 사이(수평)협조를 구함자료 제공, 작업 지원 부탁
업무 지시서상급자에서 하급자로업무를 배정함팀장이 팀원에게 과제 부여
품의서담당자에서 결재권자로승인을 받음비용 지출, 계약 진행 전
발주서회사에서 외부 거래처로물품·용역을 주문함구매 수량과 단가 확정 후

요청한 일에 비용이 들거나 외부 업체를 써야 한다면 업무 요청서만으로는 부족할 수 있습니다. 이런 경우 받는 부서가 품의서로 따로 승인을 받는 일이 흔합니다.

작성 예시: 회의 자료용 미수금 현황 요청

소형 장비 유통사 한결테크의 영업지원팀이 11월 16일(월) 영업회의에 쓸 미수금 자료를 회계팀에 요청하는 경우입니다.

항목입력 예
요청 부서·요청자영업지원팀 서지현 대리
수신 부서·담당회계팀 박태오 주임
요청일 / 희망 완료일2026년 11월 9일(월) / 2026년 11월 13일(금)
우선순위높음
요청 제목3분기 말 기준 거래처별 미수금 현황 요청
요청 내용9월 30일 기준, 거래 중인 42곳의 미수금 잔액. 청구일로부터 90일이 지난 건은 따로 표시. 11월 16일 영업회의 자료로 사용
결과물 형태엑셀 파일 1개(거래처명, 청구일, 미수금액, 경과일수 열)

회의는 16일(월)인데 희망 완료일은 그 전 주 금요일인 13일로 잡았습니다. 회의 전에 자료를 미리 확인하고, 빠진 내용이 있으면 되묻고, 회의용으로 정리할 여유를 두기 위해서입니다. 기준일(9월 30일)과 대상 범위(42곳)를 숫자로 적어 두면 받는 쪽이 범위를 다시 묻지 않아도 됩니다. 입력란의 "예시로 채워 보기"를 누르면 각 칸에 무엇을 적는지 미리 볼 수 있습니다.

우선순위 기준 예시. 등급별 처리 기간을 부서끼리 미리 정해 두면 이견이 줄어듭니다. 예를 들면 긴급은 1영업일 이내, 높음은 3영업일 이내, 보통은 5영업일 이내로 정하는 식입니다. 등급과 기간은 회사마다 다르므로 이 숫자는 참고용입니다.

작성할 때 자주 하는 실수

1. 희망 완료일 대신 "최대한 빨리"라고 쓰는 경우

날짜가 없으면 받는 쪽은 보통 자기 업무를 먼저 끝낸 뒤 처리합니다. 날짜를 정하기 어렵다면 "늦어도 ○일까지"처럼 마지노선이라도 적으세요.

2. 모든 요청을 "긴급"으로 표시하는 경우

매번 긴급으로 표시하면 받는 부서는 등급을 믿지 않게 됩니다. 그러면 정말 급한 건이 다른 요청에 묻힙니다. 결과물이 늦을 때 실제로 어떤 일이 막히는지를 기준으로 등급을 고르세요.

3. 결과물 형태를 비워 두는 경우

숫자 몇 개를 메신저로 받으려 했는데 상대가 보고서를 만드느라 이틀을 쓰는 일이 생깁니다. 반대로 표가 필요한데 PDF로 받아 다시 입력하기도 합니다. 파일 종류와 필요한 열까지 적어 두면 이런 일을 막을 수 있습니다.

4. 필요 이상의 개인정보를 요청하는 경우

인사·총무 부서에 직원 명단을 요청하면서 목적과 상관없는 주민등록번호나 연락처까지 달라고 적는 경우가 있습니다. 개인정보는 목적에 필요한 항목만 요청하고, 요청 내용에 사용 목적을 함께 적으세요.

전달한 뒤에는 접수 확인부터

요청서를 보냈다고 해서 상대가 받아들인 것은 아닙니다. 담당자가 내용을 확인했는지, 희망 완료일 안에 처리할 수 있는지 답을 받아야 일정이 확정됩니다. 이 양식에는 접수 서명란이 따로 없습니다. PDF를 메일로 보내고 회신으로 확인을 받거나, 인쇄본 여백에 받은 담당자가 접수일과 이름을 적게 하면 됩니다. 처리 상태를 계속 챙겨야 하는 요청이 여러 건이라면 요청 제목과 완료일을 관리표에 옮겨 두세요.

자주 묻는 질문

메신저로 부탁해도 되는데 굳이 문서로 써야 하나요?

간단한 확인은 메신저로 충분합니다. 다만 작업이 하루 이상 걸리거나 결과물을 회의·보고에 써야 한다면 문서로 남기는 편이 안전합니다. 나중에 범위나 기한을 두고 말이 엇갈릴 때 기준으로 삼을 수 있습니다.

받는 부서가 희망 완료일을 맞출 수 없다고 하면요?

요청 범위를 줄이거나 일부를 먼저 받는 방법을 협의하세요. 위 예시라면 90일 경과 건만 13일에 먼저 받고 전체 목록은 다음 주에 받는 식입니다. 합의한 날짜로 요청서를 고쳐 PDF로 다시 저장해 두면 기록과 실제 일정이 맞습니다.

여러 부서에 같은 내용을 요청해도 되나요?

부서마다 맡을 부분이 다르면 요청서를 나눠 쓰는 것이 좋습니다. 요청서마다 수신 담당이 한 명으로 정해져야 책임이 분명해집니다.

결재란은 없나요?

이 양식은 요청 정보 입력에 맞춰져 있어 결재란이 없습니다. 팀장 승인이 필요한 회사라면 인쇄한 뒤 승인을 받거나 사내 결재 절차를 따로 거치세요.

입력한 내용이 저장되나요?

입력한 내용은 서버로 전송되지 않습니다. 나중에 다시 볼 요청서라면 PDF로 저장해 두세요.
